# Larry invariants

One line per rule: the rule, why it holds, the test that enforces it. A correction replaces its line.
Changing a runtime rule is a specification change, never a refactor.

## Runtime (crates/larry-runtime)

- The journal is authoritative; state is a fold over recorded facts and every projection is discardable and re-derivable. A journal from `Journal::open` lives in one `lgwks_bot::journal::RecordJournal` file under its lock: each entry is staged as the index takes it and every staged entry is synced in one write before any owner reach and before a tick returns (group commit), records hold parts and never digests, replay re-validates every entry through the contract constructors and acceptance rules, a torn tail is taken back, committed bytes that break the chain are refused, and a clone is memory-only. Why: a live-state read as truth cannot be replayed or audited, a fact an owner or caller saw must survive a kill -9, and a stored digest is a claim, not evidence (larry#75, ADR 0023). Test: `tests/sim_replay.rs` (`sim_replay_from_the_file_matches_the_memory_trace_for_every_seed`), `tests/sim_crash_restore.rs` (`sim_crash_restore_from_the_file_after_a_drop_keeps_every_acknowledged_entry`, `sim_a_torn_tail_is_taken_back_and_the_run_restores`), `journal::durable::tests` (`sim_durable_capacity_refuses_before_the_file_grows`, `a_record_carries_no_digest_and_a_tampered_part_rederives_another`).
- Nothing is dispatched without a durable intent, a recorded authorization and current freshness; the intent is written before the owner is called. Why: an effect without a prior intent is unaccountable. Test: `tests/lifecycle.rs`, `tests/sim_lifecycle.rs`.
- `EventKind` is closed and has no "dispatched" fact; a crash inside the dispatch window stays ambiguous, and the attempt count rides the outcome record the dispatch already writes rather than a new kind. Why: a convenience fact would let recovery publish a receipt for an effect that never ran, and a second write per reach is cost for a fact the outcome record can carry (larry#182, ADR 0036). Test: `tests/sim_crash_restore.rs`.
- A restored effect restores with the dispatch count the journal recorded, and nothing in memory moves before the journal's sync returns. An outcome record carries the attempt number it was observed at and `restore` reads it through `ProjectionBackend::dispatches`; a record with no count, an effect the journal leaves `Reserved`, and one the journal never mentions all restore with the whole budget spent, because the journal cannot prove a lower count. `Runtime::admit` fills the pending queue and the question book only after `sync` returns `Ok`, so a caller whose sync refuses has had neither moved and the entry on disk waits for a restore to admit it once; a refused sync latches the journal (`Journal::sync`), so every later `accept_command` or `record` in that process, a retry of the same command included, returns `RuntimeError::Durable` before the index moves, and only a restore admits the journaled command, once; a command whose `CommandAccepted` record fails (a full journal) goes back into the pending set at its place before the error returns, so the next tick or a restore reduces it once and a retry is never `DuplicateReplay` for a command held nowhere; `executor::gate::drive` names a tick that fails the sync with `ExecError::Unsealed` and keeps that journal. Why: a restart recharged the budget and reused attempt 1 under one `EffectKey`, a command the caller was told had failed to become durable was executed anyway, and a retry of a refused command was answered `DuplicateReplay` and never run in that process, and a reduce that failed after the journal took the command dropped it from memory so its retry was answered the same way (larry#182 defects 2 and 7, larry#209, larry#219, ADR 0036, ADR 0017, ADR 0041). Test: `tests/sim_budget_restore.rs` (`sim_a_restart_spends_the_recorded_dispatch_budget`), `runtime::admission::tests` (`sim_a_sync_refusal_admits_nothing_and_a_restore_admits_once`, `sim_a_retry_after_a_sync_refusal_is_refused_and_a_restore_admits_once`, `sim_a_submit_retry_after_a_sync_refusal_is_refused_and_a_restore_admits_once`, `sim_reduce::sim_a_reduce_failure_then_retry_is_never_a_silent_duplicate`, `sim_reduce::sim_a_reduce_failure_survives_restore_and_reduces_once`, `sim_reduce::sim_a_reduce_failure_interleaved_with_a_second_tenants_retries_never_crosses_tenants`).
- The dispatch fence is one `lgwks_bot::broker::Broker` environment per runtime holding the security epoch (epoch `n` is generation `n + 1`), the withdrawn operations (at most 65,536) and the offline exposure bound; after the reservation is durable a mutating reach mints a warrant over `fence::effect_key`, re-checks it with `revalidate` immediately before the owner, and counts one unit with `spend` only once the owner returns an outcome; an epoch with no generation is refused, a report of `u64::MAX` closes the fence, and observation is never gated; `restore` of a journal holding history builds `RevocationFence::restored`, whose whole offline allowance counts as spent until the first `authenticate` takes up the bound at the source's epoch, while an empty journal starts fresh. Why: a recorded decision is not a standing entitlement, a withdrawal between the mint and the handoff must hold, a saturated epoch let a reservation one epoch stale pass, and the unjournaled broker let a kill -9 and restart recharge offline authority and settings older than the source revive it (larry#76, ADR 0024; larry#99, E71, ADR 0026). Test: `tests/fence.rs`, `tests/sim_fence.rs`, `tests/sim_epochs.rs`, `fence::tests` (`a_withdrawal_between_the_mint_and_the_handoff_refuses_the_handoff`, `neighbouring_top_epochs_never_share_a_key_generation`, `revocations_saturate_at_the_broker_bound_and_the_epoch_still_fences`, `a_report_past_the_last_epoch_closes_the_fence_for_good`, `e71_a_restored_fence_reaches_nothing_until_the_source_is_contacted`, `e71_a_restored_zero_bound_stays_shut_after_contact`), `tests/fence_recovery.rs` (`e71_a_restart_recharges_no_offline_authority_and_old_settings_revive_nothing`).
- A status answer resolves only an effect the runtime sent; the live effect table is the witness. Why: without it a status reply can publish success for an effect that provably never happened. Test: `tests/e63_forged_claims.rs`.
- Replay is bit-identical; each authorization carries its own pinned snapshots and a divergence surfaces as a finding. Why: a silent replay pass proves nothing. Test: `tests/determinism.rs`, `tests/sim_replay.rs`.
- Decisions read no wall clock and iterate only ordered collections; the fold never runs in parallel; the fence holds counters and sets, no duration. Why: elapsed time or hash order would break replay and extend authority. Test: `tests/determinism.rs`, `tests/sim_budget.rs`.
- Duplicate and replayed inputs are idempotent under the same key. Why: retries must not double an effect. Test: `tests/sim_duplicates.rs`.
- A run id is one canonical UUID version 7 text with no process id in it, and a task that names an `idempotency_key` (1 to 256 bytes, no control byte) maps to the run id its retry names: the id is derived from the task digest, that key and the state directory's tenant, the runtime reports the retry as `CommandAcceptance::DuplicateReplay`, and the executor answers it from the sealed report the ledger keeps or from the recovered journal's unknown outcome, never by running the body again; a task with no key is a fresh run per submission. Why: a pid and a per-process counter repeated across a restart, so the duplicate rule never fired and a fixed pid in a container could mint a killed run's id and restore its journal as this run's (larry#182 defect 3, ADR 0037). Test: `tests/executor_idempotency_journey.rs` (`the_same_task_with_its_idempotency_key_runs_its_command_once`, `a_task_without_a_key_runs_once_per_submission`, `a_key_that_names_nothing_is_refused_typed`, `a_killed_run_with_a_key_answers_from_its_recovered_journal_and_runs_nothing`), `executor::identity::tests::sim_two_starts_that_see_one_process_id_mint_different_run_ids`, `tests/e47_protocol.rs` (`e47_a_duplicate_submission_is_reported_as_a_duplicate`).
- Tenants never share state, budgets or receipts: the runtime keeps one budget per `TenantId` (an entry enters with the tenant's first tracked run, so the map holds at most the run table's capacity), a run's cost is spent from its own tenant's counter and pinned into that tenant's authorization snapshot, a restored counter is the fold of that tenant's recorded intent costs, and a run whose recorded events name two tenants is refused with `RunTenantMismatch` by the fold, live and at restore. Why: one principal's agent must not act on another's data, and one tenant's spend must never refuse another tenant's effect (larry#208). Test: `tests/sim_budget.rs` (`sim_budget_is_per_tenant`, `sim_budget_restore_refuses_two_tenants_for_one_run`, `sim_budget_restore_keeps_each_tenants_remainder`, `sim_budget_two_tenants_keep_their_own_remainder`, `sim_budget_seeded_tenants_keep_their_own_remainders`), `tests/sim_multitenant.rs` (`sim_multitenant_five_tenants_complete_together`, `sim_multitenant_denial_is_per_tenant`).
- Cancellation stops new work and completes only once every owned effect is reconciled; a `Reserved` or observed-but-unresolved effect holds the run in `Cancelling`, across restore, bounded by the reconciliation budget. Why: the stop control in LICENSE Part B.4.3 must be real, and a cancelled run must not hide an effect that may have happened (larry#119). Test: `tests/sim_cancel.rs` (`sim_cancel_unresolved_observed_effect_holds_cancellation_open`, `sim_cancel_seeded_delays_hold_unresolved_open`).
- Hostile or malformed input is refused with a typed error, never a panic. Why: the harness reads untrusted text all day. Test: `tests/hostile_input.rs`.
- Test doubles never ship: `owner::fixture` compiles only for this crate's tests or under the `fixture` feature, and only the crate's own dev-dependency turns it on. Why: a scripted owner resolves to `None` and would bypass binding in a real build (larry#68). Test: `owner::fixture::tests::an_exhausted_script_reports_unknown_never_success`, `cargo build --bins --locked`.
- Each capability has one estate owner; a module moves onto lgwks_bot row by row per larry#68 and the Larry copy is deleted in the same change. Why: kernel absorption, one owner per capability (province#4, #7). Test: each row's PR shows that row's suites green before and after on the same seeds; row 1 (clock, larry#74) is held by `runtime::instant::tests::larry_keeps_no_clock_of_its_own`, row 2 (journal file, larry#75: Larry keeps no framing, chain or lock code) by `tests/sim_crash_restore.rs` (`sim_a_second_opener_is_refused_while_the_first_holds_the_file`), row 3 (fence, larry#76) by `fence::tests::larry_keeps_no_fence_rule_of_its_own`, row 4 (gate, larry#77) by `replay::tests::larry_keeps_no_coverage_rule_of_its_own`, row 5 (effect retry, larry#78) by `runtime::retry::tests::larry_keeps_no_retry_rule_of_its_own`, and the rows still open are review-only, owner Director, 2026-11-03, until larry#68 closes.
- The tick's one instant is `lgwks_bot::clock::Clock` read as elapsed time since the Unix epoch, and a live host builds that clock with `runtime::instant::live_clock` so the tick instant and an authority expiry share one timeline; authority expiry is `lgwks_bot::skew::lease_holds` at `RuntimeSettings::skew_bound`, zero by default; the clock never reads earlier within a process, so a rollback reaches the runtime only across a restart and changes no fence answer. Why: E30 pins expiry as an input, a second clock would be a second copy, and a zero-origin clock put the executor's 60 s lease 56 years away (larry#74, larry#182). Test: `runtime::instant::tests::a_sample_is_the_reading_placed_after_the_epoch`, `runtime::instant::tests::a_live_clock_is_anchored_at_the_epoch_not_zero`, `executor::gate::tests::the_executors_lease_and_the_runtimes_tick_share_one_timeline`, `tests/e63_forged_claims.rs` (`e63_a_proof_past_its_lease_is_refused_before_the_owner_is_reached`), `tests/sim_reconcile.rs` (`sim_lease_expiry_matches_the_pinned_lease_for_every_seed`), `tests/fence.rs` (`e71_neither_sleeping_nor_a_rolled_back_clock_recharges_offline_authority`), `tests/determinism.rs` (`sim_replay_is_identical_for_every_seed_and_its_cost_is_printed`).
- An open retry-safe effect is re-dispatched only when `lgwks_bot::retry::retry_admissible` admits it, over the `EffectKey` its intent derives; the effect's authority lease (pinned `observed_at` to `valid_until`) is both the deadline and the deduplication window, a refusal other than authority records one `Unknown` and spends the dispatch budget, and a refusal for authority alone is the fence's. Why: a resend past the approval behind it is consent by timeout (E30), and a second retry rule beside the estate owner drifts (larry#78, ADR 0017). Test: `runtime::retry::sim::sim_retry_decision_matches_the_attempt_budget_for_every_seed`, `tests/sim_reconcile.rs` (`sim_reconcile_retry_past_authority_expiry_dispatches_once_and_stays_open`, `sim_reconcile_a_refused_retry_leaves_reconciliation_and_the_journal_stops_growing`, `sim_reconcile_a_restored_retry_past_expiry_never_redispatches`).
- Policy and capability coverage is `lgwks_bot::gate::GrantSet::admit` over each `Scope`'s dotted capability, and the recorded denial names the first uncovered scope in sorted order; admission mints a `cap::Auth` proof leased for the pinned validity on the runtime clock, every mutating reach presents it after the fence, and restore re-issues only the lease left. Why: a grant must hold at the call, not only at admission, and a second coverage rule beside the estate owner drifts (larry#77, ADR 0018). Test: `tests/sim_denials.rs` (`sim_denials_coverage_matches_the_reference_rule_for_every_seed`), `tests/e63_forged_claims.rs` (`e63_a_proof_past_its_lease_is_refused_before_the_owner_is_reached`, `e63_two_tenants_never_share_a_proof`), `gate::tests::a_reissued_proof_carries_only_the_remaining_lease`.
- A client's command enters through `Runtime::submit_protocol`, and every executor task does: it agrees the highest version both ranges hold (the range `RuntimeSettings` names, 1..=1 by default) and the capabilities the command needs (`SubmitCommand`; `HumanQuestion`, never when headless), requires the offer's tenant to be the command's, and refuses a full pending set with `Overloaded` and a fixed 4-tick retry; each refusal is a typed `ProtocolError` that admits and appends nothing. Why: a client refused after queueing spends capacity and journal entries, and a wall-clock backoff breaks replay (larry#101, E47, ADR 0020). Test: `tests/e47_protocol.rs` (`e47_refusals_are_actionable_scoped_and_non_mutating`, `e47_overload_backoff_is_bounded_deterministic_and_does_not_append`, `e47_seeded_negotiation_replays_the_same_trace_for_one_thousand_seeds`, `e47_a_displayed_command_through_protocol_ingress_dispatches_its_bound_effect`).
- A protocol command, displayed or not, is acknowledged only after `Runtime::admit` has journaled and synced it (its display held in memory); the pending set is the journal's commands without `CommandAccepted`, in journal order, bounded by `MAX_READY_WORK` and rebuilt by `restore` from the journal alone; a conflicting retry or another tenant's run writes nothing; a `Steer` is promoted only once every effect of its run is reconciled as succeeded, failed or compensated, and that run's later commands wait behind it. Why: an acknowledged input lost to a kill -9 is a lie to the caller, and a correction must not contradict an effect whose outcome is open (larry#100, E28, ADR 0025). Test: `runtime::admission::tests` (`sim_an_acknowledged_admission_survives_a_crash_and_is_reduced_once`, `a_correction_waits_for_its_runs_effect_to_settle`, `a_permanent_unknown_keeps_a_correction_pending`, `a_foreign_tenant_cannot_admit_onto_a_pending_run`, `the_pending_set_refuses_past_its_bound_and_recovers`).
- A question (`Ask`) and its answer (`Answer`) enter only through `submit_protocol` from a non-headless client offering `HumanQuestion`, are checked at their durable admission and journaled, and the question book is a fold over the journal; a pending question holds its `Submit` (only an `Ask`, `Answer` or `Cancel` of that run passes), an answer counts only from the question's tenant and respondent about its exact run, operation, content digest and schema, once, before expiry, on an open run with no cancellation pending, within the offered scopes; a `Submit` with a question is admitted only when approved with its exact digest and scopes, otherwise denied `NotApproved` with nothing reserved; at most `max_pending_questions` (256 by default) questions are pending. Why: expiry, cancellation or a missing human is never consent, and a question lost to a kill -9 is an approval forged or lost (larry#98, E30, D25, ADR 0027). Test: `tests/e30_questions.rs` (`e30_concurrent_questions_keep_exact_bindings_and_unrelated_waits`, `e30_expiry_and_cancellation_never_become_consent`, `e30_a_headless_client_is_refused_and_nothing_is_written`, `e30_an_approval_covers_only_its_exact_content`, `e30_pending_questions_refuse_past_their_bound_and_recover`, `sim_e30_a_question_and_its_answer_survive_a_crash`).
- Every capacity, the payload byte ceiling, the skew bound, the dispatch-attempt bound, the protocol range and the admission lease are fields of `RuntimeSettings` with the Cell 05 values as defaults; `Runtime::new` and `restore` refuse a zero or out-of-range value with `RuntimeError::BadSetting` naming the field and its range, `restore` rebuilds the projection at `settings.run_capacity`, `admit` refuses a payload past `settings.max_payload_bytes` with `PayloadTooLarge` before it is decoded or journalled, and the executor takes its policy revision from the policy record, its lease from the settings and the epoch it resolves from the runtime's fence. Why: a host that set 4,096 runs got a projection built at the default 1,024 that could not rebuild its own journal, a zero bound was clamped rather than refused, and an executor constant is a second copy of a runtime rule (larry#212, ADR 0056). Test: `tests/sim_runtime_settings.rs` (`sim_a_runtime_set_to_4096_runs_fills_2000_and_restores_them`, `sim_a_payload_one_byte_past_the_ceiling_is_refused_and_one_at_it_is_admitted`, `sim_every_bad_setting_value_is_refused_by_name`), `executor::gate::tests::task_settings_derive_the_revision_from_the_policy_record`.

## Contracts (crates/larry-contracts)

- `larry-contracts` owns no state, reads no clock and performs no I/O. Why: the algebra must stay pure to be replayable. Test: `crates/larry-contracts/tests/construction.rs`.

## Workspace and dependencies

- One workspace, one lockfile, one lint set; no second repository. Why: the split runtime repo drifted and was deleted (2026-10-26). Test: `cargo metadata --locked`.
- Every lgwks_* pin is the newest release, and the documents name the locked ones. Why: estate rule ESTATE-LATEST (2026-11-03), and a doc naming an old pin is drift (larry#178, #180). Test: rust-guard ESTATE-LATEST at Edit and pre-commit, `governance::tests::governance_names_the_locked_lgwks_deps`, `governance::tests::the_cargo_sweep_names_every_locked_estate_release`.
- A third-party crate cites an open `gap` issue on Logical-Works-Inc/logicalworks-crates on its manifest line. Why: every dependency is later replaced by the estate. Test: rust-guard GAP.
- One SQLite engine per binary: `lgwks_deps/sqlite` (the executor ledger, ADR 0004), so Loco's `db-sqlite` stays off until logicalworks-crates#849 closes. Why: both link `sqlite3` at different `libsqlite3-sys` majors (docs/dependencies/cargo-sweep.md). Test: `cargo tree --locked -i libsqlite3-sys` names one version, and `cargo metadata --locked` refuses to resolve both.
- The executor writes a command's group leader into the ledger right after spawn and removes that row only once `process_group_exists` reports the group gone; a group that survives its reap keeps its row, so the next start tries again, and every start reaps the rows left behind. The window between spawn and that row is not closed; it measured p50 4.40 ms, p99 14.25 ms, max 26.01 ms (ADR 0042). A person's cancel (`run_command`'s `cancelled` input, polled at most 25 ms apart, larry#242) kills, reaps and unlists the group the same way, and the command's record says `interrupted`, never together with `timed_out`. Why: a kill -9 of the executor runs no destructor, so its groups outlive it (larry#85), a row removed while its group lives drops the only name the next start has (larry#214), and a person's Esc must end the running command, not the next step. Test: `tests/executor_journey.rs` (`a_kill_9_of_the_executor_is_reaped_by_the_next_start`, `sim_a_kill_at_every_point_between_spawn_and_insert_leaves_no_group_after_restart`, `a_timed_out_command_has_its_whole_group_killed`), `executor::session::sim::sim_esc_before_during_after_command`, `executor::ledger::tests::a_surviving_group_keeps_its_row`, `executor::sim_ledger` (`sim_racing_starts_settle_every_dead_row_and_leave_none_for_every_seed`, `sim_a_saboteur_damages_rows_and_no_group_outside_its_identity_dies_for_every_seed`).
- Each executor task's runtime journal is `journals/<task>.journal` under the state directory and is removed once the task returns, kept when the store refused it; every start, after the reap, recovers at most 1024 journals in name order whose run is not live, a run being live while a process holds its journal's lock (a held lock is skipped): replayed, restored with an owner that reaches nothing, ticked once so the reservation settles as `OutcomeUnknown` under `RequiresHuman`, and kept as `<task>.recovered`, or `<task>.refused` when its bytes are refused. Why: a kill -9 mid-task must lose no acknowledged fact, recovery must never run a dead task's body again (larry#75, ADR 0023), and a task name is one run id with no process id in it, so liveness is the journal's own lock rather than a pid a container can reuse (larry#182 defect 3, ADR 0037). Test: `tests/executor_journey.rs` (`a_kill_9_mid_task_leaves_a_journal_the_next_start_restores_without_rerunning`, `a_passing_and_a_failing_command_report_their_exit_codes`), `tests/executor_idempotency_journey.rs` (`a_killed_run_with_a_key_answers_from_its_recovered_journal_and_runs_nothing`), `tests/sim_crash_restore.rs` (`sim_two_tenants_journals_stay_separate_across_a_crash`).
- Executors sharing a state directory open and migrate the ledger one at a time under the kernel-released `executor.db.lock`; that lock is taken by a try-lock loop bounded by 60 s on a monotonic clock, and a lock held past it is refused with `ExecError::LedgerLockTimeout`, never waited on forever. A `killpg` refused with `EPERM` is repeated, and a group is probed, until 5 s have passed on the one `lgwks_bot::clock::Clock` the caller built with `runtime::instant::live_clock` (the ledger's reap takes that clock from its caller, and the saboteur sim drives the same wait on a virtual clock its probe advances, larry#308), never on a count of yields, then confirmed by the group-gone probe. Why: concurrent first opens failed "database is locked" (logicalworks-crates#872, #873); an unbounded `flock` let one stuck executor block every open, and a probe count measured yields, not time, so a loaded host ended the wait early and an idle one late (larry#214, larry#268); Darwin refuses a group holding a zombie with `EPERM` while BSD sends no member the signal (larry#131). Test: `executor::ledger::tests::concurrent_first_opens_of_one_fresh_ledger_all_succeed`, `executor::ledger::tests::a_held_ledger_lock_returns_the_typed_timeout`, `executor::sim_group` (`sim_the_group_gone_wait_ends_on_the_injected_clock`, `sim_a_group_that_never_goes_away_stops_at_the_bound`, `sim_the_eperm_retry_ends_on_the_injected_clock`), `tests/executor_journey.rs` (`two_tasks_at_once_never_share_a_workspace`, `a_timed_out_command_has_its_whole_group_killed`).
- Every test wait ends on its event or on one deadline: a ledger witness ends when its run drops its guard, on unwind too, and at `GROUP_PROBE_DEADLINE` on `larry_runtime::live_clock`; a ledger read refused while its writer holds the lock is retried inside `deadline::PATIENCE` and the last cause is the failure; and the governance RSS sampler ends on that same deadline, never on a count of probes. Why: a count measures the scheduler, so a loaded host decides the pass, and a panic that skipped the witness's flag left the scope waiting forever (larry#294, ADR 0053). Test: `executor::session::sim::sim_a_panic_inside_run_command_ends_the_witness_and_reports_the_panic`, `tests/support/exec_cli.rs` (`sim_live_group_pid_answers_after_two_busy_reads`), `tests/support/deadline.rs` (`a_wait_whose_reads_keep_failing_names_the_last_cause`), `tests/governance_journey.rs` (`sim_the_rss_sampler_ends_on_the_deadline_not_a_probe_count`).
- A journey's fixture repository runs no background git: `maintenance.auto=false` and `gc.auto=0` are set before its first commit, so only the executor can change a tree a journey hashes. Why: `git commit` forks `git maintenance run --auto --detach`, whose object-database lock flaked the origin digest on a docs-only PR (larry#138, ADR 0007). Test: `tests/executor_journey.rs` (`a_fixture_origin_starts_no_background_maintenance`, `a_hostile_command_leaves_the_origin_byte_identical`).
