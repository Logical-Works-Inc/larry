# Larry invariants

One line per rule: the rule, why it holds, the test that enforces it. A correction replaces its line.
Changing a runtime rule is a specification change, never a refactor.

- Governance temp-path scans retain parsed trees and their verdicts only inside one workspace snapshot (`temp_paths::snapshot`), keyed by exact source bytes and bounded at 16 MiB, while follow names resolve against the live tree (`temp_paths::follow`); changed bytes are reparsed and re-analysed, so malformed or changed source never uses a stale tree or verdict. Why: repeated checks paid tree-sitter's parse and tree-walk cost while a stale tree could hide a refusal. Test: `governance::tests` (`a_hundred_checks_of_the_tree_print_their_percentiles`, `a_cached_parse_is_invalidated_when_a_source_changes`).

## Runtime (crates/larry-runtime)

- Every stored route carries a versioned price table (micro-dollars per million tokens, revision 1 with no rates on a new row); only `larry route price` writes it, bumping the revision in the same statement, `route add` re-adding a priced route keeps the table it found, and a damaged rate is refused by name (`BadPrice`); an eval arm is priced by its route's table when declared, else by `LARRY_EVAL_PRICE_*`, and the card names the table revision. Why: an arm over a stored route must price the model its route names, at the route's own rates, without environment prices. Test: `tests/sim_route_price.rs` (`sim_route_price_is_versioned_and_typed`, `sim_concurrent_prices_bump_once_each`, `sim_every_tabled_route_prices_alone`), `tests/route_price_journey.rs` (`a_priced_route_is_versioned_and_listed`), `tests/eval_journey/priced.rs` (`a_priced_route_prices_the_arm_without_eval_price_settings`, `a_zero_priced_route_scores_at_zero_cost_with_no_eval_price_settings`, `an_unpriced_route_with_no_eval_price_settings_is_refused_naming_the_variable`), `executor::ledger_routes::tests` (`route_prices_round_trip_bump_and_refuse_damage`), `model::route::tests` (`a_price_past_the_bound_is_refused`).

- The journal is authoritative; state is a fold over recorded facts and every projection is discardable and re-derivable. A journal from `Journal::open` lives in one `lgwks_bot::kernel::journal::RecordJournal` file under its lock: each entry is staged as the index takes it and every staged entry is synced in one write before any owner reach and before a tick returns (group commit), records hold parts and never digests, replay re-validates every entry through the contract constructors and acceptance rules, a torn tail is taken back, committed bytes that break the chain are refused, and a clone is memory-only. Why: a live-state read as truth cannot be replayed or audited, a fact an owner or caller saw must survive a kill -9, and a stored digest is a claim, not evidence (larry#75, ADR 0023). Test: `tests/sim_replay.rs` (`sim_replay_from_the_file_matches_the_memory_trace_for_every_seed`), `tests/sim_crash_restore.rs` (`sim_crash_restore_from_the_file_after_a_drop_keeps_every_acknowledged_entry`, `sim_a_torn_tail_is_taken_back_and_the_run_restores`), `journal::durable::tests` (`sim_durable_capacity_refuses_before_the_file_grows`, `a_record_carries_no_digest_and_a_tampered_part_rederives_another`).
- Nothing is dispatched without a durable intent, a recorded authorization and current freshness; the intent is written before the owner is called. Why: an effect without a prior intent is unaccountable. Test: `tests/lifecycle.rs`, `tests/sim_lifecycle.rs`.
- `EventKind` is closed and has no "dispatched" fact; a crash inside the dispatch window stays ambiguous, and the attempt count rides the outcome record the dispatch already writes rather than a new kind. Why: a convenience fact would let recovery publish a receipt for an effect that never ran, and a second write per reach is cost for a fact the outcome record can carry (larry#182, ADR 0036). Test: `tests/sim_crash_restore.rs`.
- A restored effect restores with the dispatch count the journal recorded — one more when an observed retry-safe effect is unresolved, because a crash may have cut off a reach the record cannot show — and nothing in memory moves before the journal's sync returns. An outcome record carries the attempt number it was observed at and `restore` reads it through `ProjectionBackend::dispatches`; a record with no count, an effect the journal leaves `Reserved`, and one the journal never mentions all restore with the whole budget spent, because the journal cannot prove a lower count. `Runtime::admit` fills the pending queue and the question book only after `sync` returns `Ok`, so a caller whose sync refuses has had neither moved and the entry on disk waits for a restore to admit it once; a refused sync latches the journal (`Journal::sync`), so every later `accept_command` or `record` in that process, a retry of the same command included, returns `RuntimeError::Durable` before the index moves, and only a restore admits the journaled command, once; a command whose `CommandAccepted` record fails (a full journal) goes back into the pending set at its place before the error returns, so the next tick or a restore reduces it once and a retry is never `DuplicateReplay` for a command held nowhere; `executor::gate::drive` names a tick that fails the sync with `ExecError::Unsealed` and keeps that journal. Why: a restart recharged the budget and reused attempt 1 under one `EffectKey`, a command the caller was told had failed to become durable was executed anyway, and a retry of a refused command was answered `DuplicateReplay` and never run in that process, and a reduce that failed after the journal took the command dropped it from memory so its retry was answered the same way (larry#182 defects 2 and 7, larry#209, larry#219, ADR 0036, ADR 0017, ADR 0041). Test: `tests/sim_budget_restore.rs` (`sim_a_restart_spends_the_recorded_dispatch_budget`), `runtime::admission::tests` (`sim_a_sync_refusal_admits_nothing_and_a_restore_admits_once`, `sim_a_retry_after_a_sync_refusal_is_refused_and_a_restore_admits_once`, `sim_a_submit_retry_after_a_sync_refusal_is_refused_and_a_restore_admits_once`, `sim_reduce::sim_a_reduce_failure_then_retry_is_never_a_silent_duplicate`, `sim_reduce::sim_a_reduce_failure_survives_restore_and_reduces_once`, `sim_reduce::sim_a_reduce_failure_interleaved_with_a_second_tenants_retries_never_crosses_tenants`).
- A display approved at one security epoch is re-checked when a held `Submit` is reduced, so a command that waited in the pending set across a revocation dispatches nothing. Why: the display was checked only at admission, so a held command left on a generation the authority source had left behind (larry#332, E65). Test: `tests/e65_display_binding.rs` (`e65_a_held_submit_refuses_a_revocation_since_its_display`).
- One command's, effect's or run's typed refusal is recorded as a `TickItem` entry in the `TickReport` and the tick goes on; only a journal refusal (a full, refused or unprovable file) and a clock that cannot be placed end a tick, and every `RuntimeError` variant is classified once in `RuntimeError::ends_the_tick` with no wildcard arm; a pending command whose acceptance record fails with one item's error is reduced once and the loop steps past it, a command refused after its acceptance is durable never makes the loop skip the one that took its slot, and `FoldDivergence` is one item's refusal, never the tick's; a held `Submit` refused because its display's security epoch went stale writes a `CommandRefused` fact (`CommandRefusal::StaleDisplayEpoch`, ADR 0078) beside its durable `CommandAccepted` fact, so a restart reads why it never ran; a `Submit` whose operation id the live table already holds, for any tenant, is refused `DuplicateOperation` before its run is tracked or moved and writes `CommandRefusal::DuplicateOperation` the same way (larry#198, ADR 0113). Why: a bound retry whose owner target changed, a foreign tenant's command for a pending run, a second `Cancel`, a `Submit` on a non-draft run and a held `Submit` whose display epoch went stale each ended the tick before reconciliation and cancellation, so one tenant's refusal skipped every tenant's work (larry#329, larry#332), one failed acceptance re-reduced its own slot until the budget was spent so the commands behind it never ran, and a refusal that lives only in the report dies with the process that an operator restarts (larry#371), and a reused operation id was refused only after three transitions, leaving its run in `Reconciling` with no effect (larry#182 defect 8). Test: `tests/sim_duplicate_operation.rs` (`sim_a_reused_operation_id_is_refused_before_its_run_moves`), `tests/tick_refusals.rs` (`a_per_item_refusal_is_a_typed_entry_and_the_tick_goes_on`, `a_foreign_command_is_a_typed_denial_and_reconciliation_goes_on`, `a_foreign_command_after_restore_is_a_typed_denial_and_the_tick_goes_on`, `a_second_cancel_is_a_typed_denial_and_completion_goes_on`, `a_submit_on_a_non_draft_run_does_not_stop_another_tenants_effect`, `sim_a_tenants_bad_command_never_stops_another_tenants_effect`, `sim_a_command_whose_accept_fails_is_reduced_once_and_the_tick_goes_on`, `sim_a_stale_display_refusal_survives_a_restart_as_a_journal_fact`, `a_fold_divergence_is_a_recorded_refusal_and_the_tick_goes_on`), `runtime::admission::tests::sim_reduce::sim_a_refusal_after_acceptance_never_skips_the_next_pending_command`, `crates/larry-contracts/tests/construction.rs` (`canonical_kind_tags_preserve_existing_command_and_event_digests`).
- The dispatch fence is one `lgwks_bot::broker::Broker` environment per runtime holding the security epoch (epoch `n` is generation `n + 1`), the withdrawn operations (at most 65,536) and the offline exposure bound; after the reservation is durable a mutating reach mints a warrant over `fence::effect_key`, re-checks it with `revalidate` immediately before the owner, and counts one unit with `spend` only once the owner returns an outcome; an epoch with no generation is refused, a report of `u64::MAX` closes the fence, and observation is never gated; `restore` of a journal holding history builds `RevocationFence::restored`, whose whole offline allowance counts as spent until the first `authenticate` takes up the bound at the source's epoch, while an empty journal starts fresh. Why: a recorded decision is not a standing entitlement, a withdrawal between the mint and the handoff must hold, a saturated epoch let a reservation one epoch stale pass, and the unjournaled broker let a kill -9 and restart recharge offline authority and settings older than the source revive it (larry#76, ADR 0024; larry#99, E71, ADR 0026). Test: `tests/fence.rs`, `tests/sim_fence.rs`, `tests/sim_epochs.rs`, `fence::tests` (`a_withdrawal_between_the_mint_and_the_handoff_refuses_the_handoff`, `neighbouring_top_epochs_never_share_a_key_generation`, `revocations_saturate_at_the_broker_bound_and_the_epoch_still_fences`, `a_report_past_the_last_epoch_closes_the_fence_for_good`, `e71_a_restored_fence_reaches_nothing_until_the_source_is_contacted`, `e71_a_restored_zero_bound_stays_shut_after_contact`), `tests/fence_recovery.rs` (`e71_a_restart_recharges_no_offline_authority_and_old_settings_revive_nothing`).
- A status answer resolves only an effect the runtime sent; the live effect table is the witness. Why: without it a status reply can publish success for an effect that provably never happened. Test: `tests/e63_forged_claims.rs`.
- Hot effect, receipt and approval decisions use deterministic indexes over open state, and cancellation and run-capacity checks use bounded runtime indexes rather than recounting history. Why: one open user action must not pay for completed journal history. Test: `tests/open_work_cost.rs`, `tests/e30_questions.rs`, `tests/sim_replay.rs` (larry#216, ADR 0114).
- Replay is bit-identical; each authorization carries its own pinned snapshots and a divergence surfaces as a finding. Why: a silent replay pass proves nothing. Test: `tests/determinism.rs`, `tests/sim_replay.rs`.
- Decisions read no wall clock and iterate only ordered collections; the fold never runs in parallel; the fence holds counters and sets, no duration. Why: elapsed time or hash order would break replay and extend authority. Test: `tests/determinism.rs`, `tests/sim_budget.rs`.
- Duplicate and replayed inputs are idempotent under the same key. Why: retries must not double an effect. Test: `tests/sim_duplicates.rs`.
- A run id is one canonical UUID version 7 text with no process id in it, and a task that names an `idempotency_key` (1 to 256 bytes, no control byte) maps to the run id its retry names: the id is derived from the task digest, that key and the state directory's tenant, the runtime reports the retry as `CommandAcceptance::DuplicateReplay`, and the executor answers it from the sealed report the ledger keeps or from the recovered journal's unknown outcome, never by running the body again; a task with no key is a fresh run per submission. Why: a pid and a per-process counter repeated across a restart, so the duplicate rule never fired and a fixed pid in a container could mint a killed run's id and restore its journal as this run's (larry#182 defect 3, ADR 0037). Test: `tests/executor_idempotency_journey.rs` (`the_same_task_with_its_idempotency_key_runs_its_command_once`, `a_task_without_a_key_runs_once_per_submission`, `a_key_that_names_nothing_is_refused_typed`, `a_killed_run_with_a_key_answers_from_its_recovered_journal_and_runs_nothing`), `executor::identity::tests::sim_two_starts_that_see_one_process_id_mint_different_run_ids`, `tests/e47_protocol.rs` (`e47_a_duplicate_submission_is_reported_as_a_duplicate`).
- Tenants never share state, budgets or receipts: the runtime keeps one budget per `TenantId` (an entry enters with the tenant's first tracked run, so the map holds at most the run table's capacity), a run's cost is spent from its own tenant's counter and pinned into that tenant's authorization snapshot, a restored counter is the fold of that tenant's recorded intent costs, and a run whose recorded events name two tenants is refused with `RunTenantMismatch` by the fold, live and at restore; and one tenant may hold at most `capacity / max_tenants`, never less than one, of the run table, the pending set and the pending questions, past which it is refused `RunLimitReached`, `ReadyWorkFull` or `PendingFull` naming that share while another tenant still admits, runs and asks; the global bound stays first beside the share, so the run table refuses past `run_capacity` before any eviction, a command that would open a run takes its room before its acceptance is journalled, and the question book refuses past `max_pending_questions`; a terminal run whose receipt is sealed leaves the run table, so its slot frees for the tenant's next run, the projection still reads its recorded state, and its recorded tenant still refuses another tenant's command `RunTenantMismatch`. Why: one principal's agent must not act on another's data, one tenant's spend must never refuse another tenant's effect (larry#208), and one tenant's live runs, pending commands or unanswered questions must never exhaust a cap every tenant shares (larry#333). Test: `tests/sim_budget.rs` (`sim_budget_is_per_tenant`, `sim_budget_restore_refuses_two_tenants_for_one_run`, `sim_budget_restore_keeps_each_tenants_remainder`, `sim_budget_two_tenants_keep_their_own_remainder`, `sim_budget_seeded_tenants_keep_their_own_remainders`), `tests/sim_multitenant.rs` (`sim_multitenant_five_tenants_complete_together`, `sim_multitenant_denial_is_per_tenant`), `tests/sim_tenant_caps.rs` (`sim_a_tenant_at_its_share_refuses_and_another_tenant_still_admits_runs_and_asks`, `sim_a_sealed_terminal_run_leaves_the_table_and_frees_its_slot`, `sim_three_tenants_at_one_share_hold_the_global_question_bound`, `sim_three_tenants_at_one_share_hold_the_global_run_bound`, `sim_an_evicted_runs_owner_still_refuses_a_foreign_tenant`).
- Cancellation stops new work and completes only once every owned effect is reconciled; a `Cancelling` run makes no mutating reach, and the refused retry spends its retry budget so the effect stays visibly unresolved; a `Reserved` or observed-but-unresolved effect holds the run in `Cancelling`, across restore, bounded by the reconciliation budget. Why: the stop control in LICENSE Part B.4.3 must be real, a cancelled run must not hide an effect that may have happened, and a retry-safe effect kept reaching its owner after the stop (larry#119, larry#332). Test: `tests/sim_cancel.rs` (`sim_cancel_unresolved_observed_effect_holds_cancellation_open`, `sim_cancel_seeded_delays_hold_unresolved_open`, `sim_cancel_a_retry_safe_effect_never_retries_while_cancelling`).
- Hostile or malformed input is refused with a typed error, never a panic. Why: the harness reads untrusted text all day. Test: `tests/hostile_input.rs`.
- Every executor repository is absolute, canonical, outside the state directory and below the tenant's durable ledger roots, except on a local door whose tenant holds no root row yet, which allows any absolute path outside the state directory; remote doors (MCP, ACP, serve) read that tenant's ledger policy and deny when its row is absent, while local `LARRY_POLICY` remains operator-only, and the door rides in `Settings` to the one `Ledger::authorized_repo`. Why: a remote caller must not clone an arbitrary host path or inherit another tenant's authority, and a first-timer's bare `larry` must work before any provision (larry#207, ADR 0115). Test: `tests/executor_policy_journey.rs` (`a_local_exec_in_an_unprovisioned_state_runs_and_a_provisioned_root_binds_it`, `tenant_a_naming_tenant_b_repo_is_refused`), `tests/e2e_journey.rs` (`tui_journey_unprovisioned_local_reaches_the_first_approval`), `executor::ledger::tests::sim_tenant_policy_and_repository_roots_survive_reopen`.
- Test doubles never ship: `owner::fixture` compiles only for this crate's tests or under the `fixture` feature, and only the crate's own dev-dependency turns it on. Why: a scripted owner resolves to `None` and would bypass binding in a real build (larry#68). Test: `owner::fixture::tests::an_exhausted_script_reports_unknown_never_success`, `cargo build --bins --locked`.
- Each capability has one estate owner; a module moves onto lgwks_bot row by row per larry#68 and the Larry copy is deleted in the same change, and a source names a `lgwks_bot::kernel` module (`broker`, `cap`, `clock`, `dist_lease`, `effect`, `gate`, `journal`, `retry`, `skew`) only through `lgwks_bot::kernel`, never by its `#[doc(hidden)]` support path; what `kernel` lacks (`KernelError`, the `rt` stop, cancel and confinement types) is named by its support path until logicalworks-crates#1140 lands. Why: kernel absorption, one owner per capability (province#4, #7), and lgwks_bot promises compatibility for `kernel` alone, so a support path can move in a minor release (lgwks_bot #526, #1016, larry#433); test `tests/estate_surface.rs` (`larry_names_lgwks_bot_only_through_its_supported_paths`). Test: each row's PR shows that row's suites green before and after on the same seeds; row 1 (clock, larry#74) is held by `runtime::instant::tests::larry_keeps_no_clock_of_its_own`, row 2 (journal file, larry#75: Larry keeps no framing, chain or lock code) by `tests/sim_crash_restore.rs` (`sim_a_second_opener_is_refused_while_the_first_holds_the_file`), row 3 (fence, larry#76) by `fence::tests::larry_keeps_no_fence_rule_of_its_own`, row 4 (gate, larry#77) by `replay::tests::larry_keeps_no_coverage_rule_of_its_own`, row 5 (effect retry, larry#78) by `runtime::retry::tests::larry_keeps_no_retry_rule_of_its_own`, and the rows still open are review-only, owner Director, 2026-11-03, until larry#68 closes.
- The tick's one instant is `lgwks_bot::kernel::clock::Clock` read as elapsed time since the Unix epoch, and a live host builds that clock with `runtime::instant::live_clock` so the tick instant and an authority expiry share one timeline; authority expiry is `lgwks_bot::skew::lease_holds` at `RuntimeSettings::skew_bound`, zero by default; the clock never reads earlier within a process, so a rollback reaches the runtime only across a restart and changes no fence answer. Why: E30 pins expiry as an input, a second clock would be a second copy, and a zero-origin clock put the executor's 60 s lease 56 years away (larry#74, larry#182). The executor's three time decisions read that injected clock too, never `Instant::now` or `SystemTime::now`: the command timeout (`wait_for_status` against a deadline read on `run_command`'s live clock), the model retry budget (`ModelClient` holds a `Clock`) and the admission expiry (`admit_and_run` and `recover_one` build one clock and start the lease at its reading), so a seeded run on a virtual clock drives each (larry#436, SD-4). Test: `executor::run::tests::sim_the_command_timeout_decides_on_the_injected_clock`, `tests/sim_model_client/clock.rs` (`sim_the_retry_budget_stops_on_the_injected_clock`, `sim_a_clock_that_never_moves_never_spends_the_deadline`), `executor::gate::sim_clock::sim_the_admission_expiry_reads_the_injected_clock`, `runtime::instant::tests::a_sample_is_the_reading_placed_after_the_epoch`, `runtime::instant::tests::a_live_clock_is_anchored_at_the_epoch_not_zero`, `executor::gate::tests::the_executors_lease_and_the_runtimes_tick_share_one_timeline`, `tests/e63_forged_claims.rs` (`e63_a_proof_past_its_lease_is_refused_before_the_owner_is_reached`), `tests/sim_reconcile.rs` (`sim_lease_expiry_matches_the_pinned_lease_for_every_seed`), `tests/fence.rs` (`e71_neither_sleeping_nor_a_rolled_back_clock_recharges_offline_authority`), `tests/determinism.rs` (`sim_replay_is_identical_for_every_seed_and_its_cost_is_printed`).
- An open retry-safe effect is re-dispatched only when `lgwks_bot::kernel::retry::retry_admissible` admits it: `dispatched` is the `EffectKey` the last mutating reach warranted (after a restore, the key its intent names at its recorded attempt), `proposed` the digest of the intent a resend carries, the deduplication contract only the owner's `EffectOwner::deduplication_window` (default `None`), and an effect no reach sent carries `EffectEvidence::NotApplied`; the effect's authority lease (pinned `observed_at` to `valid_until`) is the deadline, a refusal other than authority records one `Unknown` and spends the dispatch budget, and a refusal for authority alone is the fence's; a mutating reach with no live entry is denied `AuthorityExpired`, and a `spend` refusal after the owner ran is the tick refusal `RuntimeError::Unspent`, never `fenced`. Why: a resend past the approval behind it is consent by timeout (E30), a second retry rule beside the estate owner drifts (larry#78, ADR 0017), and one key passed as both inputs and a contract minted from the submitter's own strategy let an endpoint that never deduplicated get three sends (larry#197, ADR 0112). Test: `tests/sim_retry_window.rs` (`sim_a_retry_needs_the_owners_window_or_proof_it_never_left`), `runtime::retry::sim::sim_retry_decision_matches_the_attempt_budget_for_every_seed`, `tests/sim_reconcile.rs` (`sim_reconcile_retry_past_authority_expiry_dispatches_once_and_stays_open`, `sim_reconcile_a_refused_retry_leaves_reconciliation_and_the_journal_stops_growing`, `sim_reconcile_a_restored_retry_past_expiry_never_redispatches`).
- A strategy that leaves an unknown permanent (`RequiresHuman`, `AlwaysCompensate`) reaches no owner, and every reconciliation pass it takes spends one unit of the reconciliation budget, so an effect left open that was never sent appends at most `max_effect_attempts` `Unknown` records and is then left visibly unresolved rather than growing the journal every tick; `restore` reads that budget from the journal's recorded `Unknown` outcomes, so a restart appends no more. Test: `tests/sim_reconcile.rs` (`sim_reconcile_a_fenced_unknown_records_at_most_the_attempt_budget`), `tests/sim_budget_restore.rs` (`sim_a_crash_at_every_point_never_spends_past_the_budget`).
- Policy and capability coverage is `lgwks_bot::gate::GrantSet::admit` over each `Scope`'s dotted capability, and the recorded denial names the first uncovered scope in sorted order; admission mints a `cap::Auth` proof leased for the pinned validity on the runtime clock, every mutating reach presents it after the fence, and restore re-issues only the lease left. Why: a grant must hold at the call, not only at admission, and a second coverage rule beside the estate owner drifts (larry#77, ADR 0018). Test: `tests/sim_denials.rs` (`sim_denials_coverage_matches_the_reference_rule_for_every_seed`), `tests/e63_forged_claims.rs` (`e63_a_proof_past_its_lease_is_refused_before_the_owner_is_reached`, `e63_two_tenants_never_share_a_proof`), `gate::tests::a_reissued_proof_carries_only_the_remaining_lease`.
- A client's command enters through `Runtime::submit_protocol`, and every executor task does: it agrees the highest version both ranges hold (the range `RuntimeSettings` names, 1..=1 by default) and the capabilities the command needs (`SubmitCommand`; `HumanQuestion`, never when headless), requires the offer's tenant to be the command's, and refuses a full pending set with `Overloaded` and a fixed 4-tick retry; each refusal is a typed `ProtocolError` that admits and appends nothing. Why: a client refused after queueing spends capacity and journal entries, and a wall-clock backoff breaks replay (larry#101, E47, ADR 0020). Test: `tests/e47_protocol.rs` (`e47_refusals_are_actionable_scoped_and_non_mutating`, `e47_overload_backoff_is_bounded_deterministic_and_does_not_append`, `e47_seeded_negotiation_replays_the_same_trace_for_one_thousand_seeds`, `e47_a_displayed_command_through_protocol_ingress_dispatches_its_bound_effect`).
- A protocol command, displayed or not, is acknowledged only after `Runtime::admit` has journaled and synced it (its display held in memory); the pending set is the journal's commands without `CommandAccepted`, in journal order, bounded by `MAX_READY_WORK` and rebuilt by `restore` from the journal alone; a conflicting retry or another tenant's run writes nothing; a `Steer` is promoted only once every effect of its run is reconciled as succeeded, failed or compensated, and that run's later commands wait behind it.
