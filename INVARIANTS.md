# Larry invariants

One line per rule: the rule, why it holds, the test that enforces it. A correction replaces its line.
Changing a runtime rule is a specification change, never a refactor.

## Runtime (crates/larry-runtime)

- The journal is authoritative; state is a fold over recorded facts and every projection is discardable and re-derivable. A journal from `Journal::open` lives in one `lgwks_bot::journal::RecordJournal` file under its lock: each entry is staged as the index takes it and every staged entry is synced in one write before any owner reach and before a tick returns (group commit), records hold parts and never digests, replay re-validates every entry through the contract constructors and acceptance rules, a torn tail is taken back, committed bytes that break the chain are refused, and a clone is memory-only. Why: a live-state read as truth cannot be replayed or audited, a fact an owner or caller saw must survive a kill -9, and a stored digest is a claim, not evidence (larry#75, ADR 0023). Test: `tests/sim_replay.rs` (`sim_replay_from_the_file_matches_the_memory_trace_for_every_seed`), `tests/sim_crash_restore.rs` (`sim_crash_restore_from_the_file_after_a_drop_keeps_every_acknowledged_entry`, `sim_a_torn_tail_is_taken_back_and_the_run_restores`), `journal::durable::tests` (`sim_durable_capacity_refuses_before_the_file_grows`, `a_record_carries_no_digest_and_a_tampered_part_rederives_another`).
- Nothing is dispatched without a durable intent, a recorded authorization and current freshness; the intent is written before the owner is called. Why: an effect without a prior intent is unaccountable. Test: `tests/lifecycle.rs`, `tests/sim_lifecycle.rs`.
- `EventKind` is closed and has no "dispatched" fact; a crash inside the dispatch window stays ambiguous. Why: a convenience fact would let recovery publish a receipt for an effect that never ran. Test: `tests/sim_crash_restore.rs`.
- The dispatch fence is one `lgwks_bot::broker::Broker` environment per runtime holding the security epoch (epoch `n` is generation `n + 1`), the withdrawn operations (at most 65,536) and the offline exposure bound; after the reservation is durable a mutating reach mints a warrant over `fence::effect_key`, re-checks it with `revalidate` immediately before the owner, and counts one unit with `spend` only once the owner returns an outcome; an epoch with no generation is refused, a report of `u64::MAX` closes the fence, and observation is never gated; `restore` of a journal holding history builds `RevocationFence::restored`, whose whole offline allowance counts as spent until the first `authenticate` takes up the bound at the source's epoch, while an empty journal starts fresh. Why: a recorded decision is not a standing entitlement, a withdrawal between the mint and the handoff must hold, a saturated epoch let a reservation one epoch stale pass, and the unjournaled broker let a kill -9 and restart recharge offline authority and settings older than the source revive it (larry#76, ADR 0024; larry#99, E71, ADR 0026). Test: `tests/fence.rs`, `tests/sim_fence.rs`, `tests/sim_epochs.rs`, `fence::tests` (`a_withdrawal_between_the_mint_and_the_handoff_refuses_the_handoff`, `neighbouring_top_epochs_never_share_a_key_generation`, `revocations_saturate_at_the_broker_bound_and_the_epoch_still_fences`, `a_report_past_the_last_epoch_closes_the_fence_for_good`, `e71_a_restored_fence_reaches_nothing_until_the_source_is_contacted`, `e71_a_restored_zero_bound_stays_shut_after_contact`), `tests/fence_recovery.rs` (`e71_a_restart_recharges_no_offline_authority_and_old_settings_revive_nothing`).
- A status answer resolves only an effect the runtime sent; the live effect table is the witness. Why: without it a status reply can publish success for an effect that provably never happened. Test: `tests/e63_forged_claims.rs`.
- Replay is bit-identical; each authorization carries its own pinned snapshots and a divergence surfaces as a finding. Why: a silent replay pass proves nothing. Test: `tests/determinism.rs`, `tests/sim_replay.rs`.
- Decisions read no wall clock and iterate only ordered collections; the fold never runs in parallel; the fence holds counters and sets, no duration. Why: elapsed time or hash order would break replay and extend authority. Test: `tests/determinism.rs`, `tests/sim_budget.rs`.
- Duplicate and replayed inputs are idempotent under the same key. Why: retries must not double an effect. Test: `tests/sim_duplicates.rs`.
- Tenants never share state, budgets or receipts. Why: one principal's agent must not act on another's data. Test: `tests/sim_multitenant.rs`.
- Cancellation stops new work and completes only once every owned effect is reconciled; a `Reserved` or observed-but-unresolved effect holds the run in `Cancelling`, across restore, bounded by the reconciliation budget. Why: the stop control in LICENSE Part B.4.3 must be real, and a cancelled run must not hide an effect that may have happened (larry#119). Test: `tests/sim_cancel.rs` (`sim_cancel_unresolved_observed_effect_holds_cancellation_open`, `sim_cancel_seeded_delays_hold_unresolved_open`).
- Hostile or malformed input is refused with a typed error, never a panic. Why: the harness reads untrusted text all day. Test: `tests/hostile_input.rs`.
- Test doubles never ship: `owner::fixture` compiles only for this crate's tests or under the `fixture` feature, and only the crate's own dev-dependency turns it on. Why: a scripted owner resolves to `None` and would bypass binding in a real build (larry#68). Test: `owner::fixture::tests::an_exhausted_script_reports_unknown_never_success`, `cargo build --bins --locked`.
- Each capability has one estate owner; a module moves onto lgwks_bot row by row per larry#68 and the Larry copy is deleted in the same change. Why: kernel absorption, one owner per capability (province#4, #7). Test: each row's PR shows that row's suites green before and after on the same seeds; row 1 (clock, larry#74) is held by `runtime::instant::tests::larry_keeps_no_clock_of_its_own`, row 2 (journal file, larry#75: Larry keeps no framing, chain or lock code) by `tests/sim_crash_restore.rs` (`sim_a_second_opener_is_refused_while_the_first_holds_the_file`), row 3 (fence, larry#76) by `fence::tests::larry_keeps_no_fence_rule_of_its_own`, row 4 (gate, larry#77) by `replay::tests::larry_keeps_no_coverage_rule_of_its_own`, row 5 (effect retry, larry#78) by `runtime::retry::tests::larry_keeps_no_retry_rule_of_its_own`, row 6 (projection, larry#79) by `projection::tests::larry_keeps_no_projection_of_its_own`, and the rows still open are review-only, owner Director, 2026-11-03, until larry#68 closes.
- The tick's one instant is `lgwks_bot::clock::Clock` read as elapsed time since the Unix epoch, and authority expiry is `lgwks_bot::skew::lease_holds` at zero skew; the clock never reads earlier within a process, so a rollback reaches the runtime only across a restart and changes no fence answer. Why: E30 pins expiry as an input, and a second clock would be a second copy (larry#74). Test: `runtime::instant::tests::a_sample_is_the_reading_placed_after_the_epoch`, `tests/fence.rs` (`e71_neither_sleeping_nor_a_rolled_back_clock_recharges_offline_authority`), `tests/determinism.rs` (`sim_replay_is_identical_for_every_seed_and_its_cost_is_printed`).
- An open retry-safe effect is re-dispatched only when `lgwks_bot::retry::retry_admissible` admits it, over the `EffectKey` its intent derives; the effect's authority lease (pinned `observed_at` to `valid_until`) is both the deadline and the deduplication window, a refusal other than authority records one `Unknown` and spends the dispatch budget, and a refusal for authority alone is the fence's. Why: a resend past the approval behind it is consent by timeout (E30), and a second retry rule beside the estate owner drifts (larry#78, ADR 0017). Test: `runtime::retry::sim::sim_retry_decision_matches_the_attempt_budget_for_every_seed`, `tests/sim_reconcile.rs` (`sim_reconcile_retry_past_authority_expiry_dispatches_once_and_stays_open`, `sim_reconcile_a_refused_retry_leaves_reconciliation_and_the_journal_stops_growing`, `sim_reconcile_a_restored_retry_past_expiry_never_redispatches`).
- Policy and capability coverage is `lgwks_bot::gate::GrantSet::admit` over each `Scope`'s dotted capability, and the recorded denial names the first uncovered scope in sorted order; admission mints a `cap::Auth` proof leased for the pinned validity on the runtime clock, every mutating reach presents it after the fence, and restore re-issues only the lease left. Why: a grant must hold at the call, not only at admission, and a second coverage rule beside the estate owner drifts (larry#77, ADR 0018). Test: `tests/sim_denials.rs` (`sim_denials_coverage_matches_the_reference_rule_for_every_seed`), `tests/e63_forged_claims.rs` (`e63_a_proof_past_its_lease_is_refused_before_the_owner_is_reached`, `e63_two_tenants_never_share_a_proof`), `gate::tests::a_reissued_proof_carries_only_the_remaining_lease`.
- A client's command enters through `Runtime::submit_protocol`, and every executor task does: it agrees the highest version both ranges hold (1..=1 today) and the capabilities the command needs (`SubmitCommand`; `HumanQuestion`, never when headless), requires the offer's tenant to be the command's, and refuses a full pending set with `Overloaded` and a fixed 4-tick retry; each refusal is a typed `ProtocolError` that admits and appends nothing. Why: a client refused after queueing spends capacity and journal entries, and a wall-clock backoff breaks replay (larry#101, E47, ADR 0020). Test: `tests/e47_protocol.rs` (`e47_refusals_are_actionable_scoped_and_non_mutating`, `e47_overload_backoff_is_bounded_deterministic_and_does_not_append`, `e47_seeded_negotiation_replays_the_same_trace_for_one_thousand_seeds`, `e47_a_displayed_command_through_protocol_ingress_dispatches_its_bound_effect`).
- A protocol command, displayed or not, is acknowledged only after `Runtime::admit` has journaled and synced it (its display held in memory); the pending set is the journal's commands without `CommandAccepted`, in journal order, bounded by `MAX_READY_WORK` and rebuilt by `restore` from the journal alone; a conflicting retry or another tenant's run writes nothing; a `Steer` is promoted only once every effect of its run is reconciled as succeeded, failed or compensated, and that run's later commands wait behind it. Why: an acknowledged input lost to a kill -9 is a lie to the caller, and a correction must not contradict an effect whose outcome is open (larry#100, E28, ADR 0025). Test: `runtime::admission::tests` (`sim_an_acknowledged_admission_survives_a_crash_and_is_reduced_once`, `a_correction_waits_for_its_runs_effect_to_settle`, `a_permanent_unknown_keeps_a_correction_pending`, `a_foreign_tenant_cannot_admit_onto_a_pending_run`, `the_pending_set_refuses_past_its_bound_and_recovers`).
- A question (`Ask`) and its answer (`Answer`) enter only through `submit_protocol` from a non-headless client offering `HumanQuestion`, are checked at their durable admission and journaled, and the question book is a fold over the journal; a pending question holds its `Submit` (only an `Ask`, `Answer` or `Cancel` of that run passes), an answer counts only from the question's tenant and respondent about its exact run, operation, content digest and schema, once, before expiry, on an open run with no cancellation pending, within the offered scopes; a `Submit` with a question is admitted only when approved with its exact digest and scopes, otherwise denied `NotApproved` with nothing reserved; at most 256 questions are pending. Why: expiry, cancellation or a missing human is never consent, and a question lost to a kill -9 is an approval forged or lost (larry#98, E30, D25, ADR 0027). Test: `tests/e30_questions.rs` (`e30_concurrent_questions_keep_exact_bindings_and_unrelated_waits`, `e30_expiry_and_cancellation_never_become_consent`, `e30_a_headless_client_is_refused_and_nothing_is_written`, `e30_an_approval_covers_only_its_exact_content`, `e30_pending_questions_refuse_past_their_bound_and_recover`, `sim_e30_a_question_and_its_answer_survive_a_crash`).

## Contracts (crates/larry-contracts)

- `larry-contracts` owns no state, reads no clock and performs no I/O. Why: the algebra must stay pure to be replayable. Test: `crates/larry-contracts/tests/construction.rs`.

## Workspace and dependencies

- One workspace, one lockfile, one lint set; no second repository. Why: the split runtime repo drifted and was deleted (2026-10-26). Test: `cargo metadata --locked`.
- Every lgwks_* pin is the newest release. Why: estate rule ESTATE-LATEST (2026-11-03). Test: rust-guard ESTATE-LATEST at Edit and pre-commit.
- A third-party crate cites an open `gap` issue on Logical-Works-Inc/logicalworks-crates on its manifest line. Why: every dependency is later replaced by the estate. Test: rust-guard GAP.
- One SQLite engine per binary: `lgwks_deps/sqlite` (the executor ledger, ADR 0004), so Loco's `db-sqlite` stays off until logicalworks-crates#849 closes. Why: both link `sqlite3` at different `libsqlite3-sys` majors (docs/dependencies/cargo-sweep.md). Test: `cargo tree --locked -i libsqlite3-sys` names one version, and `cargo metadata --locked` refuses to resolve both.
- The executor records a command's group leader before waiting on it and removes the row only once the group is gone; every start reaps the rows left behind. Why: a kill -9 of the executor runs no destructor, so its groups outlive it (larry#85). Test: `tests/executor_journey.rs` (`a_kill_9_of_the_executor_is_reaped_by_the_next_start`).
- Each executor task's runtime journal is `journals/<task>.journal` under the state directory and is removed once the task returns, kept when the store refused it; every start, after the reap, recovers at most 1024 journals in name order whose task's executor is gone (a held lock is skipped): replayed, restored with an owner that reaches nothing, ticked once so the reservation settles as `OutcomeUnknown` under `RequiresHuman`, and kept as `<task>.recovered`, or `<task>.refused` when its bytes are refused. Why: a kill -9 mid-task must lose no acknowledged fact, and recovery must never run a dead task's body again (larry#75, ADR 0023). Test: `tests/executor_journey.rs` (`a_kill_9_mid_task_leaves_a_journal_the_next_start_restores_without_rerunning`, `a_passing_and_a_failing_command_report_their_exit_codes`), `tests/sim_crash_restore.rs` (`sim_two_tenants_journals_stay_separate_across_a_crash`).
- Executors sharing a state directory open and migrate the ledger one at a time under the kernel-released `executor.db.lock`, and a `killpg` refused with `EPERM` is repeated within the group probe bound, then confirmed by the group-gone probe. Why: concurrent first opens failed "database is locked" (logicalworks-crates#872, #873), and Darwin refuses a group holding a zombie with `EPERM` while BSD sends no member the signal (larry#131). Test: `executor::ledger::tests::concurrent_first_opens_of_one_fresh_ledger_all_succeed`, `tests/executor_journey.rs` (`two_tasks_at_once_never_share_a_workspace`, `a_timed_out_command_has_its_whole_group_killed`).
- A journey's fixture repository runs no background git: `maintenance.auto=false` and `gc.auto=0` are set before its first commit, so only the executor can change a tree a journey hashes. Why: `git commit` forks `git maintenance run --auto --detach`, whose object-database lock flaked the origin digest on a docs-only PR (larry#138, ADR 0007). Test: `tests/executor_journey.rs` (`a_fixture_origin_starts_no_background_maintenance`, `a_hostile_command_leaves_the_origin_byte_identical`).
- Every `larry exec` report is sealed with ed25519 (`lgwks_std::sign`, tag `larry.receipt.v1`) under the state directory's one key, held in owner-only `executor.db`; `accepted` is derived (no denial, a diff, every command exit 0 in time) and re-derived by `larry verify`, which refuses any altered, re-keyed or contradicted receipt; a model-command task is denied and sealed as rejected, exit 2. Why: Claude lands only work it can check offline, and a denied call reported as success is forge#158 (larry#86, ADR 0006). Test: `tests/receipt_journey.rs` (`a_tampered_receipt_is_refused`, `a_denied_run_never_reports_success`, `a_receipt_from_another_state_dir_is_untrusted`), `executor::receipt::tests::sim_sealed_reports_verify_and_every_tamper_is_refused_for_every_seed`, `executor::ledger::tests::sim_racing_first_uses_share_one_signing_key`.
- A task's model writes only the files its brief names (1 to 64 distinct repo-relative paths, never `.`, `..` or `.git`), each through one completion, never through a symlink the clone carries and never by running a command; any model or write fault refuses the task with nothing sealed, and a retry runs only when it needs no wait. Why: the clone is the origin's content, and a symlink in it would let a reply land outside the workspace (CWE-59); model commands stay denied until Nova (logicalworks-crates#846). Test: `executor::author::tests::a_symlink_anywhere_on_the_path_is_never_written_through`, `executor::author::sim::sim_malformed_briefs_get_their_exact_error_for_every_seed`, `executor::author::sim::sim_author_saboteur_symlinks_at_any_depth_are_refused_exactly`, `tests/mcp_stdio_journey.rs` (`a_rejected_or_refused_task_is_a_failed_tool_result_never_success`).
- `larry eval` runs every task of a set through `executor::execute`, checks the whole set, both prices and the model key before the first completion, prices in whole micro-dollars and costs in `u128` picodollars, scores a gateway refusal as the arm's with its cost unknown (`cost_complete: false`), stops on any other failure, and removes every origin it makes, a dead run's on the next start. Why: two arms are comparable only on one code path and one set, a mistake must spend nothing, a float rounds a cost per target, and a refusal priced at zero flatters the arm (larry#87, ADR 0009). Test: `eval::sim::sim_eval_costs_match_wide_arithmetic_and_cards_keep_their_invariants`, `eval::sim::sim_eval_fat_finger_sets_get_their_exact_error`, `tests/eval_journey.rs` (`a_fat_fingered_price_or_set_spends_nothing`, `a_lying_gateway_is_scored_as_refusals_and_the_arm_keeps_going`, `a_killed_eval_leaves_nothing_the_next_run_does_not_collect`).
- Every task `executor::execute` runs (`larry exec`, `larry_submit_task`, `larry eval`) is a displayed `WorkProposal` on a `larry_runtime::runtime::Runtime`, and its body runs only inside that runtime's bound owner reach, at most once; it needs `file.read` and `process.spawn`, a brief adds `file.write` and `model.invoke`, and `LARRY_POLICY` (unset: those four; empty: none; an unknown name refused, exit 1) is the state directory's policy; a refusal is sealed as rejected with `gate: policy_refuses: <first scope in Scope order>` and nothing cloned, written, spawned or invoked. Why: a gate no user path reaches guards nothing, and three callers checking for themselves is three gates (larry#164, ADR 0019). Test: `tests/executor_journey.rs` (`exec_denies_a_brief_task_when_the_policy_lacks_file_write`, `exec_denies_every_command_when_the_policy_is_empty`, `exec_refuses_an_unknown_policy_name`), `tests/sim_exec_gate.rs` (`sim_exec_gate_matches_the_scope_rule_for_every_seed`).
- Loco, where it lands (approval mail #91, operational tables), never serves routes, dispatches an effect, authorizes or holds authority; its tables are projections the journal rebuilds. Why: `lgwks_bot::app` is the one HTTP edge (ADR 0021), and a Loco job or row beside the journal is a second record (larry#70). Test: review-only, owner Director, 2026-11-03, until larry#70 lands its two-tenant kill -9 falsifier.

## Product

- Synthetic data stays visibly DEMO and orchestration is never simulated; the driver's frames equal the library's for any command stream, a kill -9 of the driver or the native view leaves the next session clean and the sources untouched, and the idle view writes under 1 MiB. Why: a demo must not become evidence, and a view that repaints while idle burns the terminal (larry#147).
